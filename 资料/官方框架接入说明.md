## 在比赛 CPU 环境编译

需要 C 编译器、CMake ≥3.21；float128 残差检查需要 GCC libquadmath。官方 README 指向 MPICH，当前集群使用可用的 OpenMPI 4.1.8，已通过编译及单节点两进程通信验证。

已验证的构建命令（在远端执行）：

```bash
module purge
module load gcc/11.3.0 openmpi/4.1.8/gcc11.3.0 cmake/3.24.2
export LC_ALL=C
cd /data/home/sunyc/solverchallenge26
cmake -S src -B build -DSC26_PROBLEM=02 -DSC26_BUILD_MPI=ON \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=gcc \
  -DCMAKE_PREFIX_PATH=/data/home/sunyc/solverchallenge26/deps/hypre
cmake --build build --target MPI_iterative_solver --parallel 2
ctest --test-dir build --output-on-failure
```

配置时显式选择 `gcc`，确保使用已加载的 GCC 11.3.0。当前环境的默认 `/usr/bin/cc` 是 GCC 4.8.5。

## 数值求解基线

在获分配计算节点执行框架入口：

```text
mpirun -np <进程数> ./build/bin/MPI_iterative_solver <矩阵文件> <右端文件> 0 0
```

最后两项分别为索引基和系统类型；本队当前 T2 入口使用实数系统类型 0，PETSc 二进制为零基。提交 `scripts/t2-small.sbatch` 验证小样例，再提交 `scripts/t2-baseline.sbatch` 运行两档精度。

远端 T2 输入为：

