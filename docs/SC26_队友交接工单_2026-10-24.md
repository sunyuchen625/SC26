## 二、任务与验收

### 1. 优先向测试组确认正式合同

一次性询问以下三组事项，保存答复人、日期、原文、适用范围及实际框架附件：

1. **怎么交、谁运行：**程序提交地址、代码/链接文件/可执行文件及依赖与报告清单；测试组是否重建并运行，还是验收队伍运行记录；是否可预检；如何最终确认、重交，什么回执算有效；截止时刻对应哪个时区。
2. **用什么框架和启动方式：**正式版本、允许修改的路径及共享 CMake/驱动/计量文件；MPI 实现、进程/线程与启动命令；实际解析的计时行和单位；转换/传输边界、设备完成、显存指标、原始残差与输出文件、十右端输入/复用/汇总规则。公开 README 写 MPICH，现有实验使用 OpenMPI；公开 CPU 驱动把秒数打印成 `ms`，需明确实际验收口径。
3. **GPU 怎么纳入：**能否 T2 用国产 GPU、其余题用 CPU；本队网页登记账号 `TravisSun`、Linux 用户 `travissun`，项目 `ac3k88uz8y`、分区 `hx1hdnormal` 的单卡单进程、16 CPU、58 GiB 配置能否计分；使用我方还是固定启动配置，授权有效期如何；HIP 能否沿用 MPI C 入口，还是必须实现专用 GPU 接口，测试组是否提供 HIP 框架。

**交回物：**一张“问题—答复—适用版本/配置—剩余项”表，以及实际框架、包清单、启动示例和提交说明。公开的报名表、会议报告表不能替代程序提交通道。已有问题稿见[正式合同核查与计划](FORMAL_ENTRY_GPU_CONTRACT_2026-10-23.md)。

### 2. 开展真正独立的 CPU 复现

由队友本人在独立目录，从上述 CPU 包开始，按[CPU 独立复现指南](REPRODUCE_CPU_2026-10-03.md)执行：

- 新构建九个 CPU 目标，24 个已知解案例通过，保存源码清单、CMake 缓存和二进制摘要。
- 完成以下四项，每项五次完整求解：

| 全量复现项 | 内部验收条件 |
| --- | --- |
| T2 低档 | 原始系统 float128 相对残差 `<1e-6`，源码默认投影/容差 |
| T7 | 原始系统 float128 相对残差 `<1e-6`，默认 ILU(0)/容差 |
| T5 | 原始相对残差 `≤5e-9`，五次内部 `converged=1`，默认 MGR/450/5e-9 |

全量 T2 使用代码默认值，清除 `SC26_RTOL`、`SC26_PROJECT_CONSTANT` 两项数值覆盖。保留指南所需的目录、构建设置。原始残差由既有检查器在第五次求解后核查；六位小数答案文件不能代替内存解验证。

**交回物：**执行人、账号、目录、新构建与新作业号、完整 `.out/.err`、`solver.log`、进程计时/内存及退出记录。每项要求进程/启动器成功、调度终态 `COMPLETED 0:0`，保存完整五轮记录。协调者以前的作业不能作为队友本人复现。

### 3. 按确认的合同完成最小适配与 GPU 资格验证

- 先选定实际入口，再改必要部分。当前通过测试的是 **MPI C 驱动中的 HIP 实现**；独立的 `problem02/gpu_iterative_solver.cu` 仍是未实现模板。若测试组要求该接口，需要完成真正的 HIP 适配及构建/计量接入。
- 数值 AMG/预条件器准备必须计时；不得放进排除计时的上传回调。GPU 计算须在计时边界内完成，按库完成语义或必要同步处理。**不能从约 3.9 秒原型均值中减去探针耗时，生成“正式成绩”。**
- 正式配置改变时，验证受影响的已知解、完整 T2 低档及对应计时/资源/映射；已有证据仍适用时直接复用。多进程配置需要记录实际进程—设备映射并在该配置下验证，单进程结果不能代替。
- 资格验证保存正式框架/允许修改范围、源码清单、依赖/构建/二进制身份、输入、实际启动命令、五次收敛、原始残差 `<1e-6`、成功退出和调度终态、实际计时字段/单位及资源记录。
- 平台选型按各自正式计时字段统一单位比较，沿用 S4：耗时低至少 10% 为优先目标；较小优势需匹配重复、同期 CPU 对照与分离的真实逐轮范围。只重验失效的比较覆盖。
- 若拟采用 GPU T2，队友需具备已授权 DCU 访问，并复现最终 GPU T2 包/启动；保留原四项 CPU 复现。这是 T2 的条件性补充，不重开整套实验。

**交回物：**入口/配置决定、必要改动、对应原始验证证据、CPU/GPU 选型建议及尚未关闭的条件。
