手册第 3 页的探测节点具有 128 个 CPU 核，属于手册示例整机信息；比赛官网的 GPU 平台为 32 核 CPU。提交作业必须使用本队实际获分配的核数和资源规格。

手册报告 BW1000 单卡 64 GiB 显存、80 个计算单元、wavefront 64、目标架构 `gfx936`。双卡显存需要程序显式分配与通信。CUDA 代码应检查并迁移到 HIP/对应数值库；本地 macOS 可用于阅读与编辑，DCU 编译运行需要平台环境。

## 5. 资源到账后的操作清单

### 5.1 登录与文件准备

控制台 → 命令行 E-Shell → 分配区域。文件管理入口也选择相同区域。建立工作目录：

```bash
mkdir -p ~/solverchallenge26/{src,input,output,logs,scripts}
```

在登录节点编辑代码、进行平台允许的小规模编译并提交作业。正式求解放在调度分配的计算节点。赛题已存放在官方环境，先确认目录，避免重复上传大矩阵。

### 5.2 核对工具链

手册示例使用以下命令，模块名以分配区域实际提供的版本为准：

```bash
module avail compiler/dtk
module load compiler/dtk/25.04.2
module list
which hipcc
hipcc --version
hipcc --help | grep -i arch
```

在获分配的 DCU 计算节点核对设备：

```bash
hy-smi
rocminfo | grep -E 'Name:|Marketing Name:|Vendor Name:|Device Type:|Compute Unit:'
```

若平台提供 `rocm-smi` 而未提供 `hy-smi`，使用前者。登录节点未显示 DCU 不足以判断资源分配失败。

### 5.3 首个作业

确认调度器、队列、项目、核数和 DCU 申请语法后生成作业脚本。若实际采用 Slurm，使用 `sbatch` 提交、`squeue -u "$USER"` 查询、`sacct -j <作业号>` 查验结果。

验收顺序：

1. 官方框架编译通过；接入真实求解器。
2. 小型已知解样例验证数值类型、输入、残差及计时接口。
3. T2 建立第一份全量实数基线，随后 T1/T3；T6 验证复数路径。
4. 每次保存代码版本、编译命令、模块版本、作业脚本、作业号、残差、各阶段耗时、峰值内存和完整日志。
5. 由另一名队员按同一命令复现；再推进全部 10 题。

T1 的 CPU/GPU 内存各须 ≤9 GB；T9 各须 <100 GB。平台容量不改变题目限制。参考框架完整求解阶段重复 5 次，机时预算应包含读入、验证和全部重复的实际作业时间。
