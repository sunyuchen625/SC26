低档平均阶段耗时：分析 0.0042 秒、预处理 17.6871 秒、求解与清理 3.1925 秒。高档对应为 0.0045、17.5300、4.3915 秒。两次运行都位于 `c3n12`；所有进程全程峰值已包含最终重读数据和高精度验证，rank 0 峰值分别为 4.23、4.27 GiB。

高档投影系统残差为 4.511119560369e-11，但原始系统残差仍约 5.87e-7，与实测右端常数分量一致。因此该高档结果不能视为达标。

## 方法与接口

使用 HYPRE 2.33.0 的 GMRES(50) + BoomerAMG。GMRES 最多 1000 次迭代；AMG 每次预条件应用执行一次 V-cycle，HMIS 粗化（10）、extended+i 插值（6）、每行插值最多 4 项、强连接阈值 0.25、对称混合 Gauss–Seidel 松弛（6）、每层一次扫掠。最粗层也采用迭代松弛，以适应压力方程的常数零空间。

实现位于 `资料/solverchallenge26_sample_code/problems/problem02/solver.c`，入口为 `MPI_iterative_solver`。官方框架版本为 `b66421483501021dd84aa10fc494f1dbf8e65958`，输入、分发和高精度残差检查沿用该版本；MPI 计时标签已修正为秒，与 `MPI_Wtime()` 的返回单位一致。

每轮从零初值开始，重新建立 HYPRE 矩阵、向量和 AMG 层次，求解后销毁全部库对象。官方五次重复计时保留。环境变量 `SC26_RTOL` 控制 GMRES 相对容差，低档设为 `1e-7`、高档设为 `5e-11`，分别用官方 float128 残差验证 `<1e-6`、`<1e-10`。

T2 开启 `SC26_PROJECT_CONSTANT=1`：在库内部求解右端 `b−mean(b)·1`，处理与常数零空间不相容的分量。该选项只影响库内部右端；验收始终使用官方原始矩阵和原始右端。迭代器报告的是投影系统残差，最终达标与否以官方 `Q-Check` 为准。

## 输入检查

矩阵阶数 **19,637,808**，非零元 **97,535,322**，PETSc 矩阵文件大小 1,248,975,112 字节。行非零元数量分布：2 项 23 行，3 项 2,076 行，4 项 649,497 行，5 项 18,986,212 行。

全行扫描（作业 9187886）得到：

| 指标 | 值 |
| --- | ---: |
| 最大绝对行和 | 4.9551427414e-20 |
| 最大绝对行和 / 对角元 | 6.1218905136e-15 |
| ‖A·1‖₂ | 6.9365377639e-19 |
| ‖Aᵀ·1‖₂ | 6.9364238169e-19 |
| sum(b) | 7.2741670626e-7 |
| ‖b‖₂ | 2.7976187138e-4 |
| 常数方向右端分量 / ‖b‖₂ | 5.8674343888e-7 |

4096 行确定性抽样中，对角元范围约 6.66e-12～4.12e-6，非对角元均不为正，样本中 `max|Aij−Aji|≈9.69e-27`；该对称性检查只覆盖抽样。

这些实测值表明常数向量是数值上的近零空间。对于具有精确常数左零空间的理想系统，右端常数分量会给出约 5.87e-7 的相对残差下界；原始双精度矩阵有舍入扰动，因此这不是对其精确可解性的证明。高档精度仍须以原始系统实测判定。

## 复现

远端工作目录为 `/data/home/sunyc/solverchallenge26`。源码在 `src/`，依赖安装在 `deps/hypre/`。首次部署到计算平台时，先完成 [目录部署与依赖下载](../../README.md#部署到计算平台)。

依赖构建：

```bash
module purge
module load gcc/11.3.0 openmpi/4.1.8/gcc11.3.0 cmake/3.24.2
cd /data/home/sunyc/solverchallenge26
cmake -S deps/hypre-2.33.0/src -B deps/hypre-build \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=mpicc -DCMAKE_CXX_COMPILER=mpicxx \
  -DCMAKE_INSTALL_PREFIX=/data/home/sunyc/solverchallenge26/deps/hypre \
  -DHYPRE_ENABLE_MPI=ON -DHYPRE_ENABLE_OPENMP=OFF -DHYPRE_ENABLE_PRINT_ERRORS=ON
cmake --build deps/hypre-build --parallel 2
cmake --install deps/hypre-build
```

求解器构建与验证：

```bash
cmake -S src -B build -DSC26_PROBLEM=02 -DSC26_BUILD_MPI=ON \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=gcc \
  -DCMAKE_PREFIX_PATH=/data/home/sunyc/solverchallenge26/deps/hypre
cmake --build build --target MPI_iterative_solver --parallel 2
ctest --test-dir build --output-on-failure
sbatch scripts/t2-small.sbatch
```

小样例通过后提交 `sbatch scripts/t2-baseline.sbatch`。脚本依次运行两档精度，每档保存 `solver.log`、`answer_x.rhs` 及每进程 `/usr/bin/time` 记录。按作业号在 `runs/t2-<作业号>/` 查找结果。单独运行高档可使用 `sbatch --export=ALL,SC26_RTOLS=5e-11 scripts/t2-baseline.sbatch`。

## 日志与计量口径

本地日志目录为 `logs/2026-09-22/t2/`，包含依赖构建、求解器构建、CTest、小样例及全量运行记录。

- `summary.json`：两档数值结果与内存统计。
- `jobs.log`：Slurm 状态、退出码、时间及计算节点。
- `runs/t2-9187890/1e-7/solver.log`：通过低档的五轮及官方残差。
- `runs/t2-9187935/5e-11/solver.log`：高档五轮及未达标的官方残差。
- 各运行目录的 `rank-*.time`：32 个进程的全程计时与峰值 RSS。
- `logs/t2-source-sha256.txt`：当前源码、脚本及远端可执行文件的校验值。

完整 `answer_x.rhs` 保存在远端对应运行目录。

- 官方计时为五次完整分析、准备、求解及清理的平均耗时，MPI 取各进程平均值的最大值；文件读入、最终解写出及高精度验证在该区间之外。
- `T2_PHASE_SECONDS` 分别记录每轮三个阶段的进程最大耗时；各阶段的最大值可能来自不同进程。
- 官方内存输出是验证前各进程历史峰值 RSS 之和。额外保存的每进程 GNU time 记录覆盖整个程序，包括 rank 0 重读完整矩阵和 float128 验证；各进程峰值之和是保守汇总，不是同一时刻的节点驻留内存。
- 官方 `answer_x.rhs` 仅保留六位小数；最终残差依据内存中的双精度解，不能用舍入后的文件替代其精度验收。
