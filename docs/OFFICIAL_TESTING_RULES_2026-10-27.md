## 现行计时流程

```text
初始化、数据分配、创建 solver/矩阵/向量句柄（不计时）
第1–5次：五次完整预热求解（不计时）
第6次开始前：开始正式计时
第6–10次：连续五次完整正式求解
第10次完成后：停止正式计时
释放 solver/矩阵/向量句柄（不计时）
正式平均求解时间（ms）= 正式累计时间（s）×1000÷5
```

| 项目 | 当前要求 |
| --- | --- |
| 预热与正式次数 | 先五次完整预热，再连续五次正式运行，共十次；只统计第6–10次 |
| 不计时 | 初始化、数据分配、solver/矩阵/向量句柄的创建和释放；CPU→GPU 数据传输 |
| 每次必须完成 | 算法需要的分析、分解、预处理及求解；不得复用前一次运行的计算结果 |
| 句柄复用 | 可以按新示意图保留句柄；这不等于允许复用数值分解、预条件器或前次解 |
| 排序与转换 | 不改变非零元行列坐标的存储转换可不计时；行列置换等矩阵重排必须计时 |
| 单位 | 官方结果表填写毫秒（ms），并保存正式累计时间、单位与除以五的对应关系 |
| 正确性与内存 | 使用官方示例检测接口；允许选择检测精度；第1、2题按精度行逐项填写，未达标如实标注 |
| 资源/内存 | 保留节点、MPI/线程/GPU配置及官方输出；适用的CPU/GPU内存限制及分布式求和要求仍有效 |

计时边界按操作的实际含义划分，不能仅凭旧 `analyse/preprocess/solve_cleanup` 函数名决定。必要的结构/数值分析、AMG/预条件器 Setup、分解和求解必须完整计入每次运行。输入数据可保留，上一轮计算得到的分解、预条件器或解不能代替本轮计算；每轮按相同规定设置初始状态。GPU设备工作须在相应正式计时终点前完成。GPU→CPU回传未被新模板列为排除项；所选路径包含该操作时，不能直接套用双向传输皆排除的旧约定，应结合求解/检测接口明确实际边界，有歧义时定向确认。

应把可排除的准备与释放安排在正式累计计时区间外，并记录实际实现。若后端把句柄操作与数值工作混在同一调用中，先识别真实边界并做最小拆分；存在影响成绩的歧义时保存调用链，定向向测试组确认。T2的RHS投影、迭代行列缩放和T10均衡化属于数值预处理，每次从未修改的输入重新执行并计时，不能随格式转换一起缓存。MPI按适用示例的同步/归约完成约定覆盖整个正式区间，不能用单个rank或逐轮局部计时求和冒充连续区间。避免为分离计时而无依据地复制多套大型矩阵、改变算法或放宽数值容差。

## 旧记录的适用范围

CPU/GPU 现有通过记录仍证明各自原实现的数值与执行情况。它们采用旧五轮范围、秒计时，保留为实验历史。**旧均值乘1000或扣除旧探针耗时都不能变成新规成绩。** 当前未见符合新5+5流程的正式CPU/GPU原件，正式平均时间为待测。

冻结候选、当前源码及源码目录中的旧运行说明是现有实现基线，尚未完成本次5+5适配。`scripts/verify_runs.py` 和 `scripts/audit_handoff.py` 用于旧归档回放，其通过不代表新规验收。新执行任务应补相应的十次流程/正式累计计时验收，并同步最终入口的运行说明。
